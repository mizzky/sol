# N+1比較

## 計測対象

- `getOrderLogic`と同じ処理構造を再現した検証専用ローダーを使用する
- N+1版は注文一覧を1回取得した後、注文ごとに注文明細を取得する
- batch版は注文一覧と注文明細一覧をそれぞれ1回で取得する
- N+1版とbatch版で、注文・注文明細・並び順が同一であることをテストする

## 計測条件

- DBは`coffeesys_perf`を使用する
- 注文件数（N）は`10 / 100 / 500`とする
- 各条件でウォームアップを1回実行する
- 本計測を5回実行し、実行時間の中央値を採用する
- 実行時間は環境に依存するため、テストの合否条件には使用しない

## 実行コマンド

`backend`ディレクトリで以下を実行する。

```bash
go test -tags=integration ./perf \
  -run '^TestMeasureOrders(NPlusOne|Batch)$' \
  -count=1 \
  -v
```

## 結果

- N+1版のクエリ数は注文件数に応じて`1 + N`で増加した
- batch版のクエリ数はNにかかわらず2回で固定された
- N=500では、実行時間を97.0%、クエリ数を99.6%削減した
- N+1版とbatch版で、取得結果が同一であることを確認した
- batch版でも取得行数の増加に伴う実行時間の増加は残るが、DBとの往復回数は増加しない
- 実行時間は環境に依存するため、性能の回帰は時間のassertではなくクエリ数と取得結果で検証する
